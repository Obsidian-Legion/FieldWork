# Authentication and authorization

Azure Container Apps Easy Auth owns the GitHub OAuth exchange and session cookies. FIELDWORK never asks for a GitHub password, stores an access token, or requests repository access. The first successful GitHub sign-in creates a profile attached to the provider's immutable numeric user ID. No account matching by email is performed.

The Unison server uses verified `X-MS-CLIENT-PRINCIPAL-*` headers only in `FIELDWORK_AUTH=azure` mode, behind enabled Azure Easy Auth. Do not expose that mode on a server without the Azure authentication middleware: direct callers could forge those headers. The deployment starts in `locked` mode and the configuration script enables header trust only after verifying the platform's settings. Public requests cannot supply those identity headers through Azure Easy Auth.

Session discovery remains behind Easy Auth so verified claims reach the server. The browser treats an anonymous 401 as the sign-in screen. GitHub usernames come from the `urn:github:login` claim; a missing GitHub display name does not prevent sign-in. Malformed principals, conflicting GitHub IDs, and other identity providers are rejected.

Admin permissions come from the deployment's `FIELDWORK_ADMIN_IDS` allowlist of GitHub numeric IDs. A new registration is a member unless explicitly listed; request bodies cannot grant roles. Admins alone write the shared catalogue, relationships, archives, and uploads. Members can write only their own notes, completion flags, and map positions. All course-file reads require authentication, and members cannot read unreferenced or archived files.

Cloud data is stored in a private Azure Blob container using managed identity. JSON writes use Azure ETags and conditional requests to prevent lost updates between processes. Storage keys are generated by the server from validated IDs. Blob versions and seven-day soft deletion are enabled. The app does not put data or credentials in the Git repository or container image.

Local mode is an explicit development workspace with administrative access and no cloud authentication. It is restricted to `127.0.0.1`; startup rejects binding local mode to a public interface. The role tests simulate Azure identity headers on an isolated local server. They test application authorization, not the actual GitHub OAuth exchange. Live acceptance requires completing GitHub consent and verifying a member and administrator session in Azure.

The server buffers uploads and downloads in memory, with a 100 MB upload limit. The initial Azure deployment is sized for a small course library; larger media workloads should move to direct authorized Blob uploads and streaming delivery. No public user directory, password database, or account-deletion endpoint is included in this release.
